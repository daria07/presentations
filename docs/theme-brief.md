# ТЗ: новые темы оформления для слайдов

Это задание для дизайнера (человека или модели). Оно описывает не
«нарисуйте красивую презентацию», а то, как устроен наш рендер и в
каких рамках живёт тема. Рамки жёсткие: тема, выходящая за них, не
ляжет в продукт без переделки.

---

## 1. Что за продукт

Сервис собирает презентацию по теме или по готовому тексту. Модель
отдаёт структуру слайдов, сервер печатает из неё PDF.

Печать идёт так: Blade-шаблон → HTML-страница → headless Chrome →
PDF. Никакого PowerPoint, никакого InDesign. **Тема — это CSS**, и
ничего кроме CSS.

## 2. Как устроено оформление

Две независимые оси, которые сочетаются в любой комбинации:

- **Гамма** — только цвет. Десять ролей, не больше. Сейчас их десять
  штук: Туман, Графит, Глина, Шалфей, Вино, Мёд, Лагуна, Ирис, Неон,
  Ночь.
- **Тема** — характер: шрифты, кегли, скругления, линии, тени, поля.
  Сейчас их три: Строгая, Модная, Мягкая.

Итого 30 сочетаний, и **каждое должно выглядеть осознанно**. Это
главное ограничение всей работы: тема не выбирает цвета, она работает
с любыми десятью.

Технически: базовая вёрстка и базовый CSS лежат в одном файле, тема —
это файл с переопределениями поверх него. Гамма приезжает CSS-
переменными.

## 3. Что нужно сделать

Три-четыре новые темы. Каждая тема — это:

1. **Название и одна строка описания** по-русски. Примеры нынешних:
   «Строгая — прямые углы, волосяные линии, деловой тон»;
   «Модная — крупный гротеск, скругления, мягкие тени».
2. **Пара шрифтов**: заголовочный и текстовый (могут совпадать).
3. **Блок CSS-переопределений** — собственно тема.
4. **HTML-превью** со всеми десятью вёрстками, чтобы можно было
   посмотреть, не собирая проект.

Темы должны различаться **издалека**. Если две темы отличаются только
кеглем на пару пунктов — это одна тема.

---

## 4. Жёсткие ограничения

### Размер и переполнение

- Слайд ровно **338.667 × 190.5 мм** (16:9, как в PowerPoint).
- Высота фиксирована, у слайда `overflow: hidden`. **Что не влезло —
  обрезается молча.** Это не теоретическая опасность: на четырёх
  пунктах с двухстрочными описаниями текст уже наезжал на номер
  страницы.
- Поэтому все размеры задаются в **мм и pt**, не в px и не в rem.
  Это печать, а не экран.

### Цвет

- **Ни одного цвета в коде темы.** Только переменные гаммы:

    | Переменная       | Роль                                    |
    | ---------------- | --------------------------------------- |
    | `--paper`        | фон слайда                              |
    | `--ink`          | основной текст                          |
    | `--muted`        | второстепенный текст                    |
    | `--rule`         | линии и рамки                           |
    | `--accent`       | акцент                                  |
    | `--accent-ink`   | акцент потемнее, для текста по светлому |
    | `--accent-soft`  | акцентная подложка                      |
    | `--cover-bg`     | фон титульного и финального слайда      |
    | `--cover-ink`    | текст на обложке                        |
    | `--cover-accent` | акцент на обложке                       |

    Захардкоженный `#333` сломает тему на тёмных гаммах (Графит, Ночь,
    Неон). Прозрачности поверх переменных (`color-mix`, `opacity`)
    допустимы.

### Шрифты

- Только то, что есть на **Bunny Fonts / Google Fonts**.
- **Обязательна кириллица.** Красивый шрифт без кириллицы не годится,
  даже если очень хочется.
- Максимум **два семейства на тему** и **три-четыре начертания**.
  Каждое начертание вшивается в PDF в base64 — это вес файла и
  секунды на печать.

### Чего нельзя совсем

- JavaScript — его в печати нет.
- Внешние ссылки: картинки, шрифты, стили по URL. Браузер при печати в
  сеть не ходит.
- Фотографии и растровые фоны. Допустимы CSS-градиенты, геометрия на
  CSS и инлайновый SVG.
- Менять разметку. Тема переопределяет стили существующих классов и
  не добавляет своих элементов.
- Свои иконки. Набор фиксирован: часы, календарь, песочные часы, рост,
  падение, график, стрелка, идея, цель, поиск, книга, слои, человек,
  люди, сообщение, здание, дом, галочка, предупреждение, плюс и ещё
  несколько. Они одноцветные, рисуются `currentColor`.

## 5. Вёрстки, которые нужно оформить

Десять. Каждая должна выглядеть хорошо в каждой теме — нельзя сделать
тему «для списков» и забить на матрицу.

| Вёрстка      | Что внутри                                                                        |
| ------------ | --------------------------------------------------------------------------------- |
| `title`      | титульный: заголовок, подзаголовок. Заливка `--cover-bg` на весь слайд            |
| `bullets`    | 3–5 пунктов: номер или иконка, заголовок в 2–4 слова, описание в одно предложение |
| `stats`      | 2–4 числа рядом, у каждого подпись                                                |
| `bignumber`  | одно число во весь слайд и пояснение под ним                                      |
| `timeline`   | события по годам, в хронологии                                                    |
| `process`    | 3–4 шага по порядку, с номерами                                                   |
| `comparison` | ровно две колонки: два подхода рядом                                              |
| `matrix`     | четыре ячейки, деление по двум признакам                                          |
| `quote`      | цитата и автор                                                                    |
| `closing`    | финальный: как титульный, но завершающий                                          |

Классы, с которыми работает тема:

```
.slide .slide--cover .head .eyebrow .subheading .rule-accent .pageno
.bullets .bullet .bullet-mark .bullet-mark--icon .bullet-title .bullet-text
.stats .stat .stat-value .stat-label
.bignum .bignum-value .bignum-label .bignum-note
.timeline .tl-item .tl-dot .tl-stem .tl-value .tl-label
.process .step .step-num .step-icon .step-title .step-text
.compare .compare-col .compare-title .compare-text
.matrix .cell .cell-icon .cell-title .cell-text
.quote-mark .quote-text .quote-author
h1 h2 .body .body--center
```

## 6. По чему будем судить

1. **Читается с последнего ряда.** Это проектор в переговорной, а не
   макет в Figma на 27 дюймах. Текст пунктов мельче 10 pt не годится.
2. **Работает на всех десяти гаммах.** Проверка обязательна минимум на
   трёх: светлой нейтральной (Туман), тёмной (Ночь), яркой (Неон).
3. **Темы различимы между собой** с одного взгляда.
4. **Ничего не обрезается** на предельном содержании: пять пунктов с
   описаниями в 150 знаков, заголовок в 50 знаков в две строки.
5. **Характер есть.** Три нынешние темы — деловая, модная, мягкая.
   Новая тема должна отвечать на вопрос «для кого она»: научная
   конференция, продуктовый питч, школьный доклад, отчёт совету
   директоров — а не быть «ещё одной нейтральной».

---

## 7. Формат сдачи

На каждую тему:

- **HTML-файл** — самодостаточный, со всеми десятью вёрстками на
  реальном содержании (не «Заголовок слайда» и не lorem ipsum),
  с переключателем гамм, чтобы посмотреть хотя бы три.
- **Блок CSS** — только переопределения, в том же виде, в каком он
  ляжет в проект.
- **Название, описание, пара шрифтов** — строкой.

---

## 8. Как давать это задание модели

Текст выше — только половина дела. Вместе с ним приложи реальные файлы
проекта, по ним видно больше, чем по любому описанию:

- `resources/views/deck/deck.blade.php` — базовая вёрстка и базовый CSS
- `resources/views/deck/styles/precise.blade.php` — пример готовой темы
- `config/deck.php` — все десять гамм с конкретными цветами

И попроси начать не с кода, а с описания замысла: для кого тема, какая
пара шрифтов и почему, что в ней главный приём. Разногласия дешевле
обсуждать на трёх абзацах, чем на готовом CSS.

---

## 9. Чего это ТЗ не касается

**Новые типы слайдов.** Если захочется вёрстку, которой нет в списке
из десяти, — это не задача дизайна. Такая работа затрагивает схему
ответа модели, промпт, разбор ответа и редактор, и ставится отдельно.
